## 1. 제품 정의

> **좋아하는 밴드 때문에 "어디에 가고, 무엇을 준비하고, 다녀온 경험을 어떻게 남길까"를 한 곳에서 해결하는 팬 활동 동행 앱.**

핵심 루프는 **탐색 → 준비 → 현장 → 기록** 이다. 이름(oshi@log)이 말하듯 기록이 쌓이는 곳이 앱의 최종 가치다. 기능을 늘리기보다 이 네 단계를 끊김 없이 연결하는 것이 우선이다.

빈도 구조에 대한 합의:

- 원정·성지순례는 **연 몇 회의 저빈도 고가치** 활동이다. 설치 이유와 획득의 핵심이다.
- 주간 재방문은 **공연 준비(세트리스트·곡·응원법·콜), 소식, 새 공연 발표, 기록 회고**에서 나온다는 가설을 채택한다(추정, 측정 필요).
- 따라서 여행 기능만 앞세우고 음악·소식을 숨기면 리텐션을 잃는다. 반대로 음악 백과를 앱의 중심으로 두면 첫 화면과 운영 범위가 과도해진다.

### 타깃 페르소나 (추정)

| 페르소나 | 문제 | 앱이 줘야 할 결과 |
|---|---|---|
| **1순위: 일본 거주 라이브·성지 팬** | 개장/개연, 회장, 응원법, 세트리스트를 매번 다시 찾음 | 공연 하나에서 준비·당일 확인·기록을 끝냄 |
| **2순위: 일본 국내 원정 팬(遠征)** | 다른 도시 공연 + 주변 성지 + 교통을 따로 찾음 | 공연과 주변 성지를 함께 저장. 현장에서 원문 주소·最寄駅·주의사항 바로 확인 |
| **3순위: 방일 해외 팬 / 한국 가오픈 사용자** | 일본어 공지·지도·티켓 사이트가 흩어짐. 짧은 일정, 불안정한 데이터 연결 | 한국어로 같은 여정 완료. 한국 가오픈 지표는 일본 지표와 분리해서 본다 |
| **집에서 정보를 모으는 팬** | 곡·멤버·성우·장소의 관계를 찾기 어려움. 팬 정보 신뢰도 불명확 | 공식 출처 기반 탐색. 다음 활동 저장. 경험 있는 항목에 정보 기여 |

우선 타깃은 1·2순위다. 수요 순위는 추정이며 일본 사용자 검증이 필요하다.

## 2. 설계 원칙

1. **읽기는 먼저, 로그인은 행동할 때.** 공유 링크로 들어온 비회원이 상세를 볼 수 있어야 한다. 저장·기록·작성 시점에 로그인하고 원래 화면으로 돌아온다.
2. **현장에서는 큰 사진보다 주소·시간·주의사항·주요 버튼.** 한 손 조작, 큰 글자, 오프라인에서도 저장한 정보는 남는다.
3. **상태는 정직하게.** "갈 예정 / 다녀옴(자기신고) / 위치 확인됨"을 구분한다. 서버 확인 전에는 완료로 표시하지 않는다. 미전송을 저장 완료로 표시하지 않는다.
4. **같은 공연은 어느 화면에서도 같은 상태.** 홈·목록·캘린더·상세가 서로 모순되지 않는다.
5. **보상은 기록의 부산물.** 팬 레벨·칭호·도감은 유지하되 홈의 주목적을 차지하지 않는다. 방문 횟수 경쟁이 무리한 방문을 유도하지 않게 한다.
6. **권리가 확인된 콘텐츠만.** 공식 이미지·가사·번역은 사용 허락 범위 안에서만 제공한다.
7. **하단 탭은 고정.** 탭 위치나 하단 바를 상황에 따라 바꾸지 않는다.

## 4. 핵심 사용자 여정

| 여정 | 트리거 → 화면 → 완료 | 편하게 만드는 조건 |
|---|---|---|
| **① 링크로 처음 들어오기** | 공유받은 장소/공연/기록 카드 → 비회원 상세 → 저장(로그인) 또는 공식 안내 | 읽기 먼저. 로그인 후 원래 행동으로 복귀. 위치 권한 없이도 열람 |
| **② 원정 준비** | 공연 날짜 확정 → 공연 상세 → 회장 주변 성지 → 저장 목록 | 여행 편집기부터 만들지 않는다. 지역·밴드 필터, 원문 주소, 저장 정보의 갱신 시각 |
| **④ 라이브 참전** | 전날/당일 → 홈의 오늘 공연 → 개장/개연·회장·응원법 → 공연 후 기록 | 공연 시작 후에도 당일 카드 유지. 세트리스트 스포일러 가리기 선택 |
| **⑤ 성지 현장 방문** | 역 도착 → 저장한 장소 → 주소/주의/길찾기 → 방문 인증 | 저장 정보 오프라인 열람. GPS 실패 시 이의신청 안내. 주거지 등은 안전한 공개 지점 인증 |
| **⑥ 돌아와서 기록·공유** | 방문 완료 → 내 기록 → 팁·후기 작성 / 기록 카드 공유 | 장소 연결 자동 유지. 로컬 초안 복구. 사진 권리·촬영 제한·개인정보 확인 |
| **⑦ 방문 없는 날** | 관심 밴드 새 소식 → 홈 → 곡·멤버·관련 공연/장소 → 다음 활동 저장 | 음악·인물 탐색은 독립적으로 열리고 공연·장소로 자연스럽게 연결 |
| **⑧ 공연 없는 순례 여행** | 지역·작품 선택(예: 川崎) → 지역 허브 → 스폿 저장 → 오늘 목록 → 현장 → 旅 앨범 → 선택 공개 레포 | 공연 없이 시작 가능. 일정 변경(비·휴무) 시 빼기·대체. 미방문은 실패가 아님. 상세는 `screen-design-v1.md` §3.4 |

## 5. 정보구조 (IA)

### 5.1 현재 구조의 문제

현재 하단 탭: **홈 / 탐방 / 정보 / 마이 / 커뮤니티** (`lib/shared/main_scaffold.dart`).

- 탐방 안에 지도·이벤트·기록·도감이 함께 있어 **갈 곳 찾기와 다녀온 기록이 섞인다** (`field_explore_page.dart:81-110`).
- 정보 탭은 소식·아티스트·도구(응원법·캘린더·명대사·도감)를 섞어 담는다. 음악 아카이브는 라우트 없이 `Navigator.push`로 열린다(`field_guide_page.dart:63`).
- 캘린더·도감·기록이 여러 탭에 흩어져 **대표 위치가 불명확**하다.
- 커뮤니티 진입 시 하단 바가 `CommunitySubBottomNav`로 교체되는 모드 전환이 있다(`main_scaffold.dart:112-134`).
- 홈은 단일 프로젝트 선택에 의존하고(`field_home_page.dart:51`), 시작 시각이 지난 공연을 대상에서 뺀다(`field_home_view_data.dart:61-65`). 진행 중 공연이 홈에서 사라진다.

### 5.2 합의 탭 구성

**홈 / 지도 / 라이브 / 커뮤니티 / 마이**

| 탭 | 사용자 질문 | 역할 | 현재 대비 변화 |
|---|---|---|---|
| **홈** | 지금 무엇을 확인하면 되지? | 관심 전체의 오늘 할 일·다음 활동·소식·기록 회고. 음악·아티스트 바로가기 | 단일 프로젝트 브리핑에서 "내 관심 전체" 기본으로 |
| **지도** | 어디에 갈까? | 성지 지도↔목록, 지역·밴드 필터, 장소 상세·방문 안내 | 탐방에서 이벤트·기록·도감 분리 |
| **라이브** | 언제 무엇이 있고, 무엇을 준비하지? | 세그먼트: 일정(목록·캘린더) / 공연 준비 / 음악·아티스트 아카이브 | 정보 탭의 음악·아티스트·응원법·캘린더 흡수 |
| **커뮤니티** | 다른 팬에게 묻고 나눌까? | 질문·팬 소통·여행후기 | 하단 바 교체 제거, 메인 탭 고정. 여행후기 작성 진입 복원 |
| **마이** | 내가 저장하고 다녀온 것은? | 저장·갈 예정·참전/방문 기록·도감·팬 레벨·칭호·설정 | 기록·도감의 대표 위치를 여기로 통일 |

음악·아티스트 아카이브는 공연 선택 없이 바로 열리는 독립 세그먼트로 유지한다. 홈 바로가기와 검색 직행도 보존한다. 소식은 홈 섹션과 아티스트 상세에서 읽는다.

### 5.3 홈 섹션 순서

1. **헤더:** 검색, 알림, 관심 범위 렌즈(기본 "내 관심 전체", 프로젝트는 필터).
2. **오늘 확인할 것:** 오늘·진행 중 공연(시작 후에도 유지), 저장 공연의 변경·취소.
3. **내 다음 활동:** 갈 예정 공연, 저장한 장소. 저장이 없으면 첫 저장을 돕는 추천.
4. **음악·아티스트 바로가기.**
5. **관심 밴드 소식:** 출처·게시일 표시.
6. **관련 팬 팁·후기:** 앞의 공연·장소와 연관된 글 우선. 일반 인기글은 뒤로.
7. **기록 회고:** 최근 방문·참전, 도감 진행도. 작게.

관심 미설정 상태에서도 전체 탐색을 허용하고, 관심 선택은 선택적 필터로 제안한다.

### 5.4 상세 화면 계층

| 상세 | 위 → 아래 | 주요 행동 |
|---|---|---|
| **장소** | 이름·일본어 원문 → 밴드와의 관계·근거 → 방문 가능 시간·촬영 제한·주의 → 주소·지도 → 현장 가이드 → 팬 팁·사진 → 관련 공연·장소 | **길찾기 / 저장**. 방문 인증은 현장 행동으로 분리 |
| **공연** | 제목·상태 → 날짜·개장/개연·회장 → 공식 안내·티켓 링크 → 내 상태(갈 예정/다녀옴/확인됨) → 응원법·곡 → 세트리스트(스포일러 가림) → 후기 | **갈 예정 / 공식 티켓**. 종료 후에는 기록 우선 |
| **곡·아티스트** | 식별 정보·소속 → 공식 링크 → 관련 공연·장소 → 응원법·콜 → 제공 가능한 가사·파트 | "공식으로 듣기", "이 곡이 나온 공연" |
| **방문/참전 기록** | 언제·어디·무엇 → 자기신고/인증 상태 → 메모·사진 → 관련 후기 | 수정·공유 카드·이의신청. 공개 범위 표시 |

지도 위치·필터·스크롤은 상세에서 돌아와도 유지한다.

## 6. 앱–서버 갭

"미사용"은 현재 소스에서 호출을 찾지 못했다는 뜻이다. 배포 트래픽 판정이 아니다.

| 구분 | 상태·근거 | 권고 |
|---|---|---|
| 공개 정책 불일치 | 앱은 홈·정보만 공개, 서버는 장소·공연 GET 공개. 홈 요약·전역 검색은 서버 인증 대상 | 비회원 화면과 공개 데이터 계약을 함께 정리. 개인 데이터·커뮤니티 일괄 공개는 금지 |
| 공연 상태 집계 차이 | 공연 상세에는 `status`, 홈 공연 DTO에는 없음(`HomeController.kt:34`). 캘린더는 앱에서 두 소스 병합(`calendar_repository_impl.dart:27`) | 같은 공연 ID·상태·최신성 표현을 모든 화면에서 맞춤. 기존 필드·nullability 변경 금지, 필드 추가로 해결 |
| 홈 API 프로젝트 필수 | `HomeController.kt:133`. "내 관심 전체" 홈에는 관심 합산 집계 필요 | gateway에 조합 엔드포인트 추가(테이블 소유 금지). 기존 엔드포인트 유지 |
| "갈 예정" 계약 없음 | `PUT …/attendance`는 `DECLARED / SELF_DECLARED / attendedAt=현재` 참석 기록(`VerificationService.kt:727`). 예정 상태가 아님 | 예정과 실제 참전을 분리하는 계약 필요. 날짜 경과로 예정을 참전으로 자동 전환 금지. 초기 범위는 §9 결정 |
| 콘텐츠 유니버설 링크 없음 | AASA가 `/oauth/x/callback`만 허용(`resources/well-known/apple-app-site-association:7`). 앱에 `share_plus` 없음 | 콘텐츠 URL 체계 → AASA/assetlinks → 앱 수신 → 비회원 랜딩 순서로 연결 |
| 북마크 목록 서버 미연결 | 서버 `GET /api/v1/users/me/post-bookmarks` 존재, 앱 목록은 로컬 provider(`post_bookmarks_page.dart:24`) | 기존 API 연결. 재설치·다른 기기 복원 |
| 장소 검색 고급 API 미사용 | `/search/unified`, `/autocomplete`, `/suggestions`, `/filters/available` (`PlaceUnifiedSearchController.kt:41`) | 확장 전에 KO/JA 검색 품질 확인 |
| 장소 댓글 필터 미사용 | `/filter/accessibility`, `/filter/routes`, `/filter/advice`, `/pinned` | 현장 팁 요약에 활용. `EASY/MODERATE/HARD`는 시설 접근성 보증이 아님 |
| 장소 사진 기여 미사용 | `/places/{id}/photos`, `/featured`, 등록·승인 API | 출처·촬영 제한·승인 운영과 묶어서 도입 |
| 가사 권리 집행 미확인 | `availability`는 권리 메타를 계산하나 가사 조회 경로에서 같은 차단이 보이지 않음(`MusicQueryService.kt:288`, `:504`) | 응답·캐시·국가/기간·권리 상태 일치 검증. P0 |
| 클라우드 초안 없음 | 앱 요청 문서(`docs/api-spec/post-drafts-api-spec.md`), 서버 컨트롤러 미발견. 로컬 초안은 있음 | P2 |
| 데이터 품질 | HANDOFF 기준 DEV: 가사 없는 곡 다수, 밴드 근거 없는 장소 236곳, 미모델 유닛 존재(`oshilog-api/HANDOFF.md`) | 콘텐츠 운영이 병목. 관리자 콘솔 작업과 함께 계획 |

앱 내부 정리 대상(서버 무관):

- 미라우팅 레거시 화면: `HomePage`(1,156줄), `BoardPage`(4,818줄) 등. 외부 호출 없음 확인된 것부터 삭제. 전체 약 13.8k줄은 개별 검증 필요.
- `/overlay/*` 중복 라우트는 스택 보존 목적이 있어 일괄 삭제하지 않는다(`app_router.dart:939`). 필요성 재검토만.
- 음악 아카이브 진입만 URL이 없다. 곡 상세 URL은 있다(`app_router.dart:530`).
- 여행후기 작성 라우트는 있으나 현행 커뮤니티에서 진입점이 끊겼다(`app_router.dart:610`, `field_community_page.dart:187`).
- i18n: 문자열은 인라인 `context.l10n(ko:, en:, ja:)`. ARB 파일은 미사용. 일본어 누락 시 대체 표시 구조(`locale_text.dart:12`)라 언어 선택만으로 일본어 완료를 주장할 수 없다.

## 7. 전문가 관점 리스크

| 관점 | 판단 |
|---|---|
| **프로덕트** | "팬 활동 전체"를 모두 핵심으로 잡으면 우선순위가 사라진다. 첫 성공 = 공연/장소 저장 → 현장 재사용. 여행·비여행 사용자를 나눠 검증 |
| **UX/IA** | 기능 수보다 중첩 메뉴와 대표 위치가 문제. 대표 위치를 정하고 교차 링크는 유지. 하단 바 교체 금지 |
| **팬 (성지·참전)** | 정확한 회장·원문 주소·개장/개연·촬영 제한이 사진보다 중요. 전회 세트리스트를 다음 공연의 확정 목록처럼 보이게 하지 않음 |
| **Flutter·오프라인** | 지도 활성 제어·클러스터링은 이미 있음(`places_map_page.dart:134`). 재작성보다 측정·재사용. 캐시가 있다고 여행 전체 오프라인 보장은 아님. 지도 타일·인증은 별도 문제 |
| **백엔드·API 계약** | 모듈 경계 유지(`docs/dev/architecture/module-and-database-contract.md`). gateway는 조합만. 기존 필드·nullability 불변, 필드 추가와 엔드포인트 버전으로 확장 |
| **커뮤니티 운영** | 신고 API만으로 운영 완성 아님. 폐업·출입 제한·사유지 노출·허위 성지는 일반 신고와 다른 처리 기준·담당자·결과 안내 필요 |
| **법무·저작권** | 공식 이미지·가사라는 사실만으로 재게시·번역·오프라인 저장 권한이 생기지 않음. 계약 미확인 |
| **법무·개인정보** | **주축은 일본 APPI**: 처리 목적, 위탁·국외 제공, 보관·삭제, 이용자 청구·사고 대응을 실제 데이터 흐름 기준으로 검토. 한국 위치정보법은 한국 가오픈 범위에서 별도 검토(가오픈은 면제 근거가 아님): 위치기반서비스 사업 신고 의무(특례 포함 확인), 개인위치정보 이용 동의·보관·파기. 현재 필수 동의에 `LOCATION_TERMS` 차단형 적용(`mandatory_consent_controller.dart:373`) — 정보 열람과 위치 기능 동의를 분리할지 결정 필요 |
| **데이터·BM** | 서버 `docs/future-development/07-bm-strategy.md`의 행동 데이터 수익화·WHALE 세그먼트·B2B 방향은 위치 데이터와 결합 시 법적·신뢰 리스크가 크다. **현재 범위 외. 별도 법률 검토 전 수집 목적 확대 금지.** "5인 이상 집계" 문구만으로 적법성이 입증되지 않음 |
| **지역 사회·에티켓** | 성지가 주거지·신사·상점인 경우 민폐 위험. 기본 인증 반경 10m(`PlaceCommandService.kt:127`). 주거지·출입 제한 장소는 안전한 공개 지점에서 인증하거나 인증 대상에서 제외 |
| **보안·부정 인증** | 서명 위치 토큰·기기 키는 있음. App Attest / Play Integrity는 서버 TODO. 랭킹·보상을 키우기 전에 필요 |
| **그로스·리텐션** | 일일 출석만으로 측정하면 방향이 틀어진다. 지표: 첫 저장률, 저장 항목 현장 재열람, 갈 예정→참전 전환, 방문 후 기여, 기록 카드 공유→신규 설치. 범용 홍보 알림보다 공연 변경·새 공연 발표 알림 |
| **접근성·KO/JA** | 핵심 여정 7개를 두 언어·큰 글자·화면낭독기로 완료 가능한지 검증. 지도에는 대체 목록. 색 외 상태 표시. 원문 주소 복사 |

## 8. 로드맵

규모: **소** = 기존 화면·연결, **중** = 앱–서버 계약·여러 상태, **대** = 신규 데이터·운영 체계.

### P0 — 신뢰와 진입

| 작업 | 규모 | 완료 판단 |
|---|---|---|
| 비회원 탐색·로그인 복귀 정책 (앱 router + 공개 데이터 계약) | 중 | 공유 링크 → 비회원 장소/공연 상세 → 로그인 → 원래 행동 복귀. 위치 거절해도 열람 |
| 공연 상태 정합성 (오늘·진행 중·변경·취소) | 중 | 같은 공연이 홈/목록/캘린더/상세에서 모순 없음. 시작 후에도 당일 카드 유지 |
| 저장 신뢰성: 북마크 목록 서버 연결, 초안·전송 대기·오프라인 상태 표시 | 중 | 재시작·통신 단절·재접속 후에도 내용 보존. 미전송을 완료로 표시 안 함 |
| 권리·출처·현장 제한 최소 기준 (가사 가용성 집행 포함) | 중+운영 | 제공 불가 콘텐츠 차단, 출처 표시, 사유지·출입 제한 인증 정책 확정 |
| 위치정보 법무 검토 (신고·동의·보관·파기, 동의 분리) | 운영 | 검토 결과 문서화, 동의 화면 정책 확정 |
