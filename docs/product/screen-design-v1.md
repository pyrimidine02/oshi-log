## 0. 설계 핵심

1. **공연 단위로 묶는다.** 공연 상세 하나에 회장·교통·공식 티켓 링크·응원법·과거 세트리스트·주변 성지·레포를 모은다. 음악 데이터는 "공연 준비 재료"로 가장 자주 소비된다는 가설이다.
2. **티켓 마감 관리는 하지 않는다.** 접수 회차·마감·당락·입금 추적과 마감 알림은 범위에서 뺐다(2026-10-02 사용자 결정). 공연 상세에는 공식 티켓 링크만 둔다.
3. **상태 축을 섞지 않는다.** 공연 상태(예정·중지·변경), 내 상태(참가 예정·참전 기록·위치 인증)는 서로 다른 축이다. 한 배지 줄에 섞지 않는다.
4. **도감은 우선 巡礼スポット集.** 현재 zukan의 `sortOrder`는 표시 순서일 뿐 이동 순서·경로·소요 시간이 없다. 추천 순서와 경로를 편집·검증한 컬렉션만 **巡礼コース**로 승격한다(서버 신규).

## 2. ホーム (홈) — "지금 내가 챙길 것"

화면의 질문: **오늘·이번 주에 놓치면 안 되는 것은?**

| 순서 | 섹션 | 내용 | 표시 조건 |
|---|---|---|---|
| 1 | 헤더 | 推しレンズ(기본 "すべての推し", 탭하면 작품·밴드 필터), 검색, 알림 | 항상 |
| 2 | **お知らせ (긴급)** | 내 공연의 당일 취소·시간 변경·회장 변경 | 해당 변경이 있을 때만 |
| 3 | **今日** | 오늘 공연: 회장, 開場/開演(JST), 주소 복사, 経路, 응원 가이드. 종료 판정은 `endTime`이 있으면 그 시각, 없으면 당일 끝까지 유지 | 오늘 참가 예정 공연이 있을 때 |
| 4 | **次の予定** | `次の参戦まで N日` + 날짜 있는 참가 예정 공연. 공연별 "前回のセトリ", "周辺の聖地" 진입 | 계획이 있을 때 |
| 5 | 楽曲・アーティスト 바로가기 | 推し 밴드 아이콘 줄 → 아카이브 | 항상 |
| 6 | 新着ライブ | 推し의 새로 발표된 공연. "参加予定に追加" | 새 발표가 있을 때 |
| 7 | みんなのレポ | 내 다음 공연·저장 장소 관련 레포 우선 | 콘텐츠가 있을 때 |
| 8 | 推しのニュース | 공식 뉴스, 출처·날짜 | 항상, 하단 |
| 9 | 私の記録 | 올해 참전·방문 수, 최근 기록 1건 | 로그인 + 기록 있을 때 |

상태별 홈:

| 상태 | 대체 구성 |
|---|---|
| 비로그인 | 近日開催のライブ, 人気の聖地, 楽曲・アーティスト, ニュース, 로그인 유도 1줄 |
| 로그인 + 推し 미선택 | 전체 프로젝트 기준 같은 구성 + 推し 선택 카드(건너뛰기 가능) |
| 推し 선택 + 계획 없음 | 3·4 대신 "近日開催のライブ" + "参加予定に追加" 안내 |
| 부분 로딩 실패 | 실패한 섹션만 재시도 행으로 대체, 다른 섹션은 표시 |

빼는 것: 배너 캐러셀, 출석 체크, 랭킹, 명대사. 운영 공지는 필요할 때 2번 위치에 한 줄로.

## 3. マップ (지도) — "어디에 갈까"

### 3.1 지도

- 전체 화면 지도 + 3단 바텀시트(접힘·중간·전체). 정보 계층은 `docs/adr/ADR-20260720-apple-map-information-hierarchy.md`를 따른다.
- 상단 칩: 작품/밴드 · 지역 · 종류(聖地 / ライブ会場 / コラボ) · 未訪問だけ · 保存済み.
- 시트 목록 행: 이름(원문), 관련 밴드, 거리 또는 지역, 방문 스탬프.
- 시트 상단 세그먼트: **スポット / スポット集**. 코스로 승격된 컬렉션만 지도에 순서 번호·경로선.
- 지도 이동 후 "このエリアで再検索" 버튼.
- 상태: 위치 거부 → 지역 선택 목록으로 동작. 위치 정확도 부족 → 안내 배너. 지도 로딩 실패 → 목록 모드로 전환. 필터 결과 없음 → 필터 해제 버튼.

### 3.2 장소 상세

| 순서 | 블록 | 내용 | 데이터 |
|---|---|---|---|
| 1 | 헤더 | 이름(원문 + 읽기), 종류, 관련 밴드·작품, 등장 장면(데이터 있을 때) | 기존 |
| 2 | **訪問の注意** | 영업시간·휴무, 촬영 가능 여부, 주거지·사유지 경고, 혼잡 주의. **출처·확인일 표시. "정보 없음"과 "허용"을 구분** | 서버 신규(현재 구조화 필드 없음, 설명 Markdown·태그만) |
| 3 | **アクセス** | 주소 복사, 最寄駅·도보 분, 「経路を調べる」→ 외부 지도/乗換案内 | 주소·좌표·외부 지도 링크는 기존. 역·도보는 서버 신규 |
| 4 | 現地ガイド | 운영자 가이드 | 기존 |
| 5 | ファンのTips | 댓글 필터(アクセス / ルート / アドバイス) 상위 3개 + 고정 댓글 | 기존 API, 앱 미사용 |
| 6 | 写真 | featured 사진. 권리 확인된 것만 | 기존 API |
| 7 | 이 장소를 포함한 스폿집·코스 | 카드 | 기존 |
| 8 | 近くのスポット | 같은 지역 | 기존 |
| 하단 고정 | 행동 | **保存** · **経路** · **チェックイン** | |

체크인 버튼 상태(숨기지 않고 이유 표시): 반경 밖("あと120m") / 위치 거부 / 정확도 부족 / 처리 중 / 인증됨 / 거절 → 이의 신청 / 공개 지점 인증 대상 장소("この場所は○○でチェックイン", 서버 정책 신규).

장소 정보 오류는 게시물 신고와 별도로 **情報の修正を提案** 시트로 받는다.

### 3.3 스폿집 / 코스 상세

- 스폿집(현재 계약): 설명, 장소 목록(표시 순서), 방문 인증 기반 진행도.
- 코스(서버 신규): 추천 방문 순서, 구간 이동 수단·거리·예상 시간, 지도 경로선.
- "保存"은 저장만 한다. 날짜를 정하면 그때 계획이 된다.

### 3.4 여행·순례 설계 (2026-10-02 보강, astra 5차 협의)

원칙: **여행 안에서 공연·순례·기록을 연결한다.** 공연이 없는 여행, 여러 작품을 함께 도는 여행도 같은 흐름으로 다룬다. 우선순위는 현장 정확성(P0) → 여행 경험 완성(P1) → 자동화(P2).

| 주제 | P0 | P1 | P2 | 서버 |
|---|---|---|---|---|
| **원문 제시** | 장소 상세 「現地で見せる」: 원문 이름·주소 큰 글자 전체 화면, 복사, 오프라인 열람. 원문 미확인은 그대로 표시 | | | DB에 `nameJa/addressJa` 있음. DTO는 선택 언어만 + ja→ko fallback 가능 → 원문 필드 추가 필요 |
| **순례 매너** | 첫 사용 매너 카드(확인 상태는 로컬), 장소별 상시 주의, 지역 상점 이용은 선택 권장(인증·보상 조건 아님) | | | 장소 가이드(Markdown·고정)로 가능 |
| **장면과 근거** | 장면 설명·화수(스포일러 가림), 공식 확인/팬 추정 구분, 철거·휴업·접근 제한 표시 | 장면 비교 화면(권리 확인 이미지만) | 고급 촬영 보조 | zukan `sceneDescription/sceneImageUrl` 있음. 권리 근거·노출 조건 신규 |
| **촬영 안내** | 안전한 공개 촬영 위치 설명 | 촬영 지점 좌표·방향 | | 신규 |
| **마지막 접근 구간** | 역 출구·실제 입구·계단·휴식·짐 보관을 가이드로 | 경로 계산에 쓰는 항목만 구조화 | | 가이드로 시작 |
| **추천 시간·계절** | 가이드 서술 | 추천 계절·시간대 구조화. "장면 재현에 좋은 시간"과 "출입 가능 시간" 분리, 출입 제한 우선 | | 검색의 `seasonNumber`는 애니 n기라 별개. 신규 |
| **공연 + 순례** | 공연 상세에 회장 주변 스폿(**직선 거리로 표시, "도보 N분" 표기 금지**), 외부 길찾기 | **開場までの巡礼**: 사용자가 정한 회장 복귀 시각 안에서 가능한 스폿 | 이동·체류 시간 반영 자동 추천 | 회장 `placeId`·시각·반경 검색 있음. 보행 시간 계산 없음 |
| **지역 허브** | | 지역 페이지(예: 川崎): 스폿·회장·기간 한정 행사·스폿집. **공연 없이 "川崎で半日巡礼"로 시작 가능** | | 지역 트리·지역별 장소 있음. 조합 화면 신규 |
| **기간 한정 스폿** | | 콜라보 카페·스탬프 랠리·타이업. **장소와 개최 건 분리**(카페는 남고 콜라보만 종료). `開催中`(기간 내)과 `営業中`(지금 영업) 구분. 여행 예정일 기준 필터 | | 개최 기간 모델 신규 |
| **오늘 목록(당일 모드)** | 저장 신뢰성·마지막 갱신 표시 | 오늘 갈 장소 선택·수동 순서·건너뛰기. 텍스트 팩 다운로드(주소·주의·연락처), 완료/실패·갱신일 | 지도 다운로드·자동 정렬 | 순서·영업시간 없음. 자동 최적화는 영업시간 확보 후 |
| **계획 변경** | | 비·휴무·혼잡 시 빼기, 실내 후보로 바꾸기. 미방문을 실패로 취급하지 않음 | 상황별 재정렬 | |
| **여행 묶음(旅)** | 자기신고·위치 인증 상태 분리 표시 | 방문·참전 기록 → 여행 후보(로컬): 병합·분리·날짜 수정. 비공개 앨범 → 레포 초안(사실만 채움, 감상은 사용자) | 다기기 동기화 | travel-reviews 생성은 기본 `PUBLISHED`라 **비공개 앨범 저장소로 재사용 불가**. `visitedAt`은 서버 기록 시각이라 여행 날짜로 확정 금지. 레포는 장소 1~20개·동일 장소 중복 금지 → 재방문 표현 보완 필요 |
| **공개 선택** | | 여행 종료 후 장소·날짜·사진별 공개 확인. 숙소·정확한 이동 시각·사진 EXIF 위치 자동 노출 금지 | | |

## 4. ライブ (라이브) — "언제 무엇이 있고, 무엇을 준비하지"

상단 세그먼트: **スケジュール / 楽曲・アーティスト**. 준비 정보는 공연 상세 안에 있다.

### 4.1 스케줄

- 기본 월별 목록, 우상단 토글로 월 캘린더.
- 필터: 推し · 지역 · 종류(ライブ / イベント / リリース / 誕生日). 생일·발매일은 종일 일정.
- 행: `10/12(月)` 날짜, 공연명, 회장·도시, 배지.
- 배지는 축별로 최대 하나씩, 글자 포함:
  - 변경: `変更あり`
  - 공연 상태: `開催前` `開催中` `終了` `中止` (`中止`만 빨강)
  - 내 상태: `参加予定` `参戦済み`
- 같은 공연 상태는 홈·지도·상세와 같은 소스에서 계산한다.

### 4.2 공연 상세 (준비 허브)

| 순서 | 블록 | 내용 | 공연 전 | 당일 | 공연 후 |
|---|---|---|---|---|---|
| 1 | 헤더 | 공연명, 공연 상태, 출연 밴드 | ○ | ○ | ○ |
| 2 | 일시 | 날짜, 開場/開演/終演(JST 명시, 終演은 있을 때만) | ○ | **강조** | ○ |
| 3 | 会場・アクセス | 회장명, 주소 복사, 最寄駅, 経路 | ○ | **최상단** | 접힘 |
| 4 | チケット | 공식 티켓 링크(`ticketUrl`) 한 줄 | ○ | 접힘 | 숨김 |
| 5 | 私の予定と記録 | 서로 독립된 3개: 参加予定(토글) / 参戦記録(자기신고) / 位置認証(시스템 판정, 사용자 선택 불가) | ○ | ○ | ○ |
| 6 | 準備 | **初参戦ガイド**(필수곡·펜라이트 색·준비물·매너), 応援ガイド, 前回公演のセトリ(출처 공연 명시), **開場までの巡礼**(§3.4), 帰りの確認(외부 경로 서비스로 終電·도착역 확인) | ○ | ○ | 접힘 |
| 7 | セットリスト | 이 공연 세트리스트. 기본 가림("ネタバレを表示") | — | 가림 | ○ |
| 8 | レポ | 이 공연 관련 게시글·레포 | — | ○ | **강조** |
| 하단 고정 | 행동 | 전: **参加予定** · **公式サイト** / 당일: **経路** · **応援ガイド** / 후: **記録する** · **レポを書く** |


예습곡 빈출 집계("このツアーでよく演奏される曲")는 서버 집계가 생긴 뒤 추가한다. 그때 기간·실제 출연 밴드·집계 공연 수·미수집 공연을 표시한다.

### 4.3 악곡·아티스트 아카이브

- 밴드 선택 칩. 세그먼트: 曲 / アルバム / メンバー.
- 곡 행: 제목, 앨범, 콜 가이드 유무.

### 4.4 곡 상세

| 순서 | 블록 |
|---|---|
| 1 | 제목·밴드·앨범·크레딧 |
| 2 | 公式で聴く (media links) |
| 3 | コール・応援 (call cues, 파트). 출처 표시 |
| 4 | この曲が演奏されたライブ (performances). 연주 주체가 곡 소속 밴드와 다를 수 있음을 표시 |
| 5 | 歌詞 — 권리 확인된 곡만. 불가하면 "公式サイトで見る" |
| 6 | 난이도(게임) — 해당 곡에 데이터 있을 때만, 접힘 |

공연 상세의 "準備"에서 들어오면 3·4를 먼저 펼친다.

### 4.5 아티스트 상세

- 밴드: 프로필 → 다가오는 공연 → 곡 → 관련 장소 → 뉴스.
- 작중 캐릭터와 실제 성우/연주자를 구분한다. 실제 출연 일정은 성우/연주자 상세에만 붙고 캐릭터에 자동 귀속하지 않는다.

## 5. コミュニティ (커뮤니티) — "다른 팬과 나누기"

- 하단 바는 메인 5탭 그대로(현재의 하단 바 교체 제거).
- 상단 세그먼트: **フォロー中 / おすすめ / 質問 / レポ**.
- 작성 시 **연결 대상 첨부**(장소·공연·곡 중 하나) → 해당 상세의 Tips/レポ 블록에 노출. 현재 게시글 생성 DTO에 연관 필드가 없어 **서버 신규**.
- レポ = travel-reviews. 현재 계약은 장소 stop 최소 1개 필수라 **공연만의 참전 레포는 불가** → 서버 계약 조정 필요. 장소를 억지로 넣게 하지 않는다. 기록 상세에서 "レポにする"로 시작.
- 신고(게시물)와 정보 정정(장소·공연 데이터)을 분리한다.
- 일본어 모더레이션 담당과 처리 기준이 준비된 뒤 공개한다.

## 9. 공통 UX 규칙과 상태

- 비로그인은 읽기 가능(서버 공개 정책 정리 전제). 저장·참가 예정·체크인·작성 시 로그인 시트 → 완료 후 **원래 행동 실행**.
- 모든 상세는 URL을 가진다(공유·푸시·유니버설 링크). 현재 `Navigator.push`로만 열리는 음악 아카이브 포함.
- 시간은 공연 시간대(JST) 기준. 단말 시간대가 다르면 병기.
- 큰 글자(200%)·320dp·다크 모드·VoiceOver 순서를 화면별 완료 조건에 포함. 골든 테스트는 ja 기준 추가.

화면마다 정의할 상태 체크리스트:

| 상태 | 처리 |
|---|---|
| 검색·필터 결과 없음 | 이유 + 필터 해제/다른 키워드 제안 |
| 첫 사용(저장·기록 없음) | 첫 행동 하나만 제안 |
| 부분 로딩 실패 | 실패 블록만 재시도, 나머지 표시 |
| 삭제·비공개 콘텐츠 딥링크 | "見つかりません" + 상위 화면으로 |
| 로그인 후 복귀 | 원래 화면·원래 행동 |
| 推し 필터 전환 | 탭별 스크롤·선택 유지 |
| 위치·알림 권한 거부 | 기능 축소 동작 + 설정 이동 버튼 |
| 인증 대기·거절 | 상태 표시 + 이의 신청 |
| 오프라인 | 저장 상세는 마지막 데이터 + "最終更新 10/2 14:30" |
| 오프라인 제출 | "送信待ち" 배지, 재전송, 중복 방지(idempotency key), 실패 시 내용 보존 |
