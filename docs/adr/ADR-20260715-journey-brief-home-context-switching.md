# ADR-20260715: 오늘의 원정 브리핑과 단일 탭 프로젝트 전환

## 상태

Accepted — 2026-07-15

## 배경

Urban Travel Field Notes 1차 홈은 개별 컴포넌트의 시각 언어는 정리됐지만,
대형 인사말, 전체 폭 프로젝트 입력 필드, 3:2 히어로, 세 개의 바로가기,
장소·일정·소식 섹션이 비슷한 비중으로 경쟁했다. 사용자는 현재 프로젝트와
다음 행동을 빠르게 파악하기 어려웠고, 대표 이벤트 또는 장소가 아래 목록에
다시 나왔다.

프로젝트 선택도 되돌리기 쉬운 전역 필터임에도 행 탭 → 초안 변경 → 하단
CTA 확정 두 단계였다. 현재 프로젝트는 요약 카드, 목록, CTA에 세 번 반복됐고,
같은 프로젝트를 다시 확정하면 selectProject()가 선택 유닛을 초기화할 수
있었다.

## 조사한 패턴

2026-07-15 기준 공식 제품·도움말에서 다음 원칙을 참고했다.

- [Airbnb Trips의 장소 기능](https://www.airbnb.com/help/article/4192):
  장소를 별도 바로가기보다 실제 여행과 지도 맥락에 연결한다.
- [Polarsteps 여행 계획](https://support.polarsteps.com/hc/en-us/articles/24265886208914-How-do-I-plan-my-trip):
  예정 장소와 날짜를 여행 단계로 묶어 보여준다.
- [AllTrails 지도 탐색](https://support.alltrails.com/hc/en-us/articles/360034969432-How-to-use-map-view-to-search-for-trails):
  목록과 지도 전환을 탐색 결과에 직접 연결한다.
- [Weverse 캘린더 업데이트](https://weverse.io/notice/29130):
  팬덤 일정과 관련 정보를 날짜 중심으로 연결한다.

시각 표현을 복제하지 않고, 활성 여행 맥락 하나 → 가장 가까운 일정 →
관련 탐방 정보라는 정보 구조만 적용한다.

## 결정

### 프로젝트 선택

공용 바텀시트는 유지한다. 이는 홈, 지도, 캘린더, 이벤트가 같은 전환 경험을
공유하고 프로젝트 수가 늘어도 스크롤 목록으로 확장할 수 있기 때문이다.

- 진입점은 테두리 입력 필드가 아닌 48dp 이상의 무테 여행 렌즈다.
- 렌즈는 여행 기준, 현재 프로젝트명, 전환만 보여준다.
- 시트 제목은 어느 세계로 여행할까요?이며 성지·일정·도감이 함께
  전환된다는 영향을 먼저 설명한다.
- 현재 여행 중복 카드, 순번, slug, 시간대, 하단 확정 CTA를 제거한다.
- 실제 현재 행만 파란 rail과 현재 배지, selected semantics를 갖는다.
- 다른 프로젝트 행을 한 번 탭하면 즉시 반환하고 전역 컨텍스트를 전환한다.
- 현재 프로젝트를 다시 탭하면 시트만 닫고 컨트롤러를 호출하지 않는다.

프로젝트 포스터·로고·대표 지역은 현재 Project 계약에 없으므로 임의
이미지나 해시 색상을 만들지 않는다. 데이터 계약이 추가되면 선택 허브의
보조 정보로 확장할 수 있다.

### 홈

홈의 단일 콘셉트는 **오늘의 원정 브리핑**이다. 사용자는 첫 화면에서 다음
세 질문에 답을 얻어야 한다.

1. 지금 어느 프로젝트를 보고 있는가?
2. 가장 가까운 일정 또는 첫 탐방지는 무엇인가?
3. 지금 누를 다음 행동은 무엇인가?

정보 순서는 다음과 같다.

1. 컴팩트 브랜드 툴바와 프로젝트 여행 렌즈
2. 가장 가까운 미래 이벤트, 없으면 첫 추천 성지
3. 대표 이벤트를 제외한 그다음 일정
4. 대표 장소를 제외한 프로젝트 성지
5. 프로젝트 소식

브리핑은 전체 폭 3:2 이미지 대신 우측 세로 이미지 스트립과 왼쪽 정보
영역을 사용한다. 이벤트는 D-day, 실제 시작 일시, 상세와 전체 일정 행동을
보여준다. 장소는 서버가 제공한 이름·지역·방문 수, 상세와 지도 행동만
사용한다. 공연장, 거리, 동행 팬 수처럼 현재 계약에 없는 값은 추정하지 않는다.

메인 하단바와 역할이 겹치는 범용 성지·일정·커뮤니티 바로가기 행은
제거한다. 실제 커뮤니티 게시물 데이터가 없는 일반 홍보 카드도 노출하지
않는다. 관련 행동은 브리핑과 각 섹션 헤더에 배치한다.

### 중복 제거 정책

composeFieldHome()은 원본 목록을 변경하지 않고 새 불변 구성을 만든다.

- 미래 이벤트를 시간순으로 정렬한다.
- 첫 이벤트를 대표로 사용하면 나머지 일정은 skip(1)이다.
- 미래 이벤트가 없으면 첫 장소를 대표로 사용하고 장소 목록은 skip(1)이다.
- 소식만 있는 프로젝트에서는 빈 브리핑 제목을 만들지 않고 소식부터 시작한다.

## 고려한 대안

### 2~3개 프로젝트 세그먼트

현재는 빠르지만 긴 다국어 프로젝트명과 프로젝트 증가에 취약하고, 지도·일정
상단을 다시 두껍게 만든다. 공용 바텀시트를 유지한다.

### 포스터 기반 프로젝트 카드 허브

개성은 강하지만 로고·이미지·요약 수치 계약이 없어 임의 데이터를 만들게 된다.
서버 계약이 준비될 때까지 이름 중심의 직접 선택을 사용한다.

### 기존 대형 히어로 유지

사진이 있는 경우는 강하지만 이미지가 없는 실제 데이터에서 빈 플레이스홀더가
첫 화면을 대부분 차지한다. 여행 판단 정보와 첫 행동을 우선하도록 축소한다.

## 영향과 검증

- 하단 내비게이션의 순서·실루엣과 기존 상세 라우트는 바꾸지 않는다.
- 프로젝트 전환은 기존 컨트롤러와 캐시·request generation을 그대로 사용한다.
- 320dp와 200% 텍스트에서 브리핑·선택 행이 overflow 없이 동작해야 한다.
- 대표 일정·장소는 하위 섹션에 중복되면 안 된다.
- 현재 프로젝트 재선택은 선택 컨트롤러 호출 수가 0이어야 한다.
- 다크 모드의 선택 강조는 기존 GBT 블루를 사용해야 한다.
- iPhone 17 Pro Max 시뮬레이터에서 실제 API 데이터와 하단바 겹침을 확인했다.
