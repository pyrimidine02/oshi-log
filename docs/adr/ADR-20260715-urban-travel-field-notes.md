# ADR-20260715: Urban Travel Field Notes 전면 UI 재설계

## 상태

Accepted — 2026-07-15

## 배경

기존 앱은 홈, 성지 탐방, 이벤트 일정, 정보, 커뮤니티, 개인 기록 기능을
각각 확장하면서 화면마다 카드·배너·그라디언트·유리 효과가 다른 방식으로
누적됐다. 기능은 존재하지만 사용자가 앱을 열었을 때 다음 행동을 결정하기
어렵고, 동일 정보가 여러 장식 카드 안에서 반복되며, 커뮤니티의 여행 후기
화면은 실제 서버 계약이 없는 샘플 데이터에 의존하고 있었다.

이번 변경은 기존 화면의 세부 스타일 조정이 아니다. 도메인 엔티티, 실제 API
프로바이더, 상세 라우트와 인증 경계는 유지하되 루트 프레젠테이션을 처음부터
다시 설계한다.

기준 런타임은 Flutter 3.44.6 / Dart 3.12.2 stable이다.

## 결정

시각 방향을 **Urban Travel Field Notes**로 정한다. 팬 굿즈를 흉내 낸 장식이나
감성 스크랩북보다, 실제 이동과 현지 판단을 돕는 정밀한 여행 도구에 가깝다.

### 시각 원칙

1. 따뜻한 종이색 캔버스와 먹색 텍스트를 기본으로 사용한다.
2. 기존 앱의 GBT 블루는 핵심 행동과 현재 상태, 틸은 장소·방문·경로
   메타데이터에 쓴다. 빨강은 오류·위험·실시간 상태처럼 의미가 있는 경우에만
   제한한다.
3. 사진과 포스터는 하나의 주인공 영역에만 크게 쓰고, 나머지는 선과 행으로
   정리한다.
4. 티켓 표현은 이벤트와 일정에만, 스탬프 표현은 완료한 방문에만 사용한다.
5. 유리 효과는 하단 내비게이션과 지도 위 제어처럼 맥락 보존이 필요한
   오버레이에만 제한한다.
6. 카드 안에 카드를 중첩하지 않고 1px 규칙선, 날짜 레일, 경로 노드로 정보
   위계를 만든다.

핵심 색상은 `paper #F7F4EE`, `raised #FFFDF8`, `ink #17202A`,
기존 브랜드 `blue #0A66C2`, `teal #2B7773`, `map line #336C8D`이다.
야간 화면은 `#0F1516`과 `#171F20`, 핵심 행동은 `#8AB4FF`, 선택 컨테이너는
`#173A67`을 사용한다. 흰색 CTA 텍스트와 기본 블루의 대비는 WCAG AA를
통과하도록 검증한다.

타이포그래피는 네트워크 폰트에 의존하지 않고 Pretendard 400–800을 앱에
번들한다. 배포본에는 [Pretendard SIL OFL 1.1 라이선스](https://github.com/orioncactus/pretendard/blob/main/LICENSE)를
함께 포함한다.

### 루트 정보 구조

| 루트 | 사용자가 해결하는 질문 | 새 화면 구조 |
| --- | --- | --- |
| 홈 | 다음에 어디로 갈까? | 컴팩트 프로젝트 렌즈 → 오늘의 원정 브리핑 → 다음 일정 → 프로젝트 성지 → 프로젝트 소식 |
| 탐방 | 주변에서 무엇을 찾을까? | 별도 하단 모드 도크 → 지도 · 이벤트 · 여정 원장 · 표본 아카이브 |
| 정보 | 무엇을 알아야 할까? | Updates · Artists · Field Kit |
| 마이 | 무엇을 다녀왔고 다음은 무엇일까? | 여행 여권 → 여정 원장 → 다음 일정 → 보관함 |
| 커뮤니티 | 다른 팬이 무엇을 발견했나? | 실제 피드와 발견 모드, 정직한 여행 노트 베타 |
| 일정 | 언제 무엇이 있나? | 항상 보이는 월 그리드 → 필터 → 날짜순 어젠다 |

홈은 과거 트렌딩 이벤트를 Next Stop으로 표시하지 않으며, 아직 시작하지 않은
이벤트를 시간순으로 정렬한다. 여행 후기의 실제 장소·방문·이벤트 연결 계약이
준비되기 전까지 샘플 후기를 실제 게시물처럼 노출하지 않는다.

### 프로젝트 선택

프로젝트 선택은 작은 라디오 목록이 아니라 앱 전체의 여행 컨텍스트를 바꾸는
행동으로 취급한다. 홈, 캘린더, 지도, 이벤트와 글 작성 화면은 하나의 공용
바텀시트를 사용한다.

- 상단의 무테 렌즈에서 현재 여행 프로젝트를 먼저 확인한다.
- 바텀시트는 프로젝트 이름과 실제 현재 상태만 갖는 64dp 이상의 행으로
  비교하며 내부 코드·시간대처럼 선택에 필요하지 않은 메타데이터는 숨긴다.
- 다른 프로젝트 행을 한 번 탭하면 즉시 전역 컨텍스트를 바꾸고 시트를 닫는다.
- 현재 프로젝트를 다시 탭하면 저장값과 유닛 필터를 건드리지 않는 no-op으로
  처리한다.
- 320dp, 200% 텍스트, 다크 모드와 스크린리더 선택 상태를 지원한다.

홈과 프로젝트 선택의 후속 정보 구조 결정은
ADR-20260715-journey-brief-home-context-switching.md에서 구체화한다.

### 지도·이벤트·유저 프로필

- 지도 상단은 56dp 단일 미션 스트립만 두고 검색을 통합한다. 프로젝트·
  지역·밴드·정렬은 지도 위 pill 군집에서 제거하고, 하단 현장 원장의
  49dp 수평 색인으로 이동한다. 장소 목록은 중첩 카드 대신 규칙선 기반
  행으로 표시한다. 현재 위치가 없을 때
  임의의 도쿄 좌표로 거리를 계산하지 않고 서버 정렬과 거리 문구를 보존한다.
- 이벤트 상단은 100dp 안에 프로젝트, 예정/아카이브, 통합 필터를 배치하고,
  목록은 하나의 `NEXT LIVE` 포스터와 날짜순 어젠다로 구성한다.
  상세는 실제 일시·장소·출연·출석·세트리스트·공식 링크를 티켓 문서 구조로
  표현한다. 제공되지 않은 값은 추정하지 않는다.
- 유저 상세는 명함형 헤더, 실제 활동 원장, 글·댓글 기록으로 구성한다.
  팔로우·차단·신고·연결 목록·프로필 편집 등 기존 권한과 동작을 유지한다.
- 기록은 장소 방문과 이벤트 출석을 실제 프로바이더에서 가져와 월별 날짜
  레일·프로젝트·인증 상태를 가진 여정 원장으로 표시한다. 통계·기록 상세·
  이벤트 상세 라우팅을 그대로 유지한다.
- 도감은 2열 카드 그리드 대신 대표 진행 표본 1개와 규칙선 기반 표본 색인을
  사용한다. 상세도 고정 3열 그리드를 제거하고 표본 헤더·진행률·방문 지점
  원장으로 이어진다. 블루는 열기/진행, 틸은 수집 완료에만 사용한다.

### 내비게이션

메인 5개 목적지 하단 바의 익숙한 실루엣과 순서는 유지한다. 커뮤니티는 사용자가
요청한 기존 전용 하단 바를 유지해 `뒤로가기 + 피드 + 발견 + 여행후기`를
제공한다. 새 커뮤니티 본문은 이 전용 바와 경쟁하는 또 다른 3분할 내비게이션을
만들지 않고, 현재 섹션 안의 추천/팔로잉 또는 인기/최신 모드만 보여준다.

기존 URL과 상세 라우트 이름은 보존하고 루트 builder만 새 화면으로 교체한다.
따라서 딥링크와 상세 화면 진입 계약을 깨지 않는다.

탐방 내부는 전역 하단바가 이미 `탐방`을 표시하므로 대형 페이지 제목과
상단 모드 선택기를 반복하지 않는다. `지도·이벤트·기록·도감` 4개 모드는
기존 요청대로 전역 하단바 위 8dp에 떠 있는 60dp 별도 도크로 유지한다.
본문은 두 하단바의 실제 크기를 한 번만 계산해 가려지지 않게 한다.

### 비동기 컨텍스트·로그 안전성

- 프로젝트 복원과 사용자의 새 선택에 generation 소유권을 두어 느린 초기화가
  최신 선택을 덮지 못하게 한다. 저장 쓰기도 순차화하고 대기 중인 이전 세대는
  폐기한다.
- 비활성 탐방 모드에서 네이티브 지도를 제거할 때 controller lease도 함께
  무효화한다. 이전 지도의 느린 실패가 새 지도 컨트롤러를 지우지 못하게
  세대와 객체 동일성을 함께 검증한다.
- 디버그 네트워크 로그는 요청·응답·오류의 중첩 Map/List와 평문 JSON,
  민감 키가 포함된 비정형 문자열을 불변 복사로 마스킹한다.
- 이벤트 출석과 로컬 outbox 작업도 요청 generation과 프로젝트 소유권을
  확인한 뒤에만 상태를 반영한다. 화면 이탈·프로젝트 전환 뒤의 늦은 결과는
  폐기한다.
- 도감 직접 진입 시 프로젝트 복원에 실패하거나 목록이 비어도 영구 로딩으로
  남기지 않는다. 오류/빈 상태와 재시도, 공용 프로젝트 선택 경로를 제공한다.

## 접근성·성능 가드레일

- 최소 터치 영역은 44–48dp로 유지한다.
- 커스텀 InkWell 제어는 외부 semantics 노드에 button, enabled, tap action을
  함께 노출하고, 여러 버튼을 가진 헤더는 자식 semantics를 제거하지 않는다.
- 320dp 폭, 한국어·영어·일본어, 라이트·다크 모드를 위젯 테스트한다.
- 비활성 내비게이션 텍스트도 반투명 배경에서 읽을 수 있는 중립색을 사용한다.
- `MediaQuery.disableAnimations`가 켜지면 선택 애니메이션 시간을 0으로 만든다.
- 홈 자동 재생 배너를 새 루트에서 제거하고, 긴 목록은 builder/sliver 기반으로
  렌더링한다.
- 일정의 빈 날짜도 동일한 크기로 탭할 수 있으며 오늘 표시는 테마의
  `onPrimary` 대비색을 사용한다.
- 방문 상태는 원본 장소 객체를 변경하지 않고 새 목록으로 투영한다.

## 고려한 대안

### 기존 화면을 점진적으로 다듬기

구현 위험은 작지만, 화면별로 누적된 서로 다른 정보 구조와 장식 규칙을 그대로
유지하게 된다. 사용자가 요청한 전면 재설계 범위에 맞지 않아 선택하지 않았다.

### 하나의 대시보드형 카드 시스템

개발은 빠르지만 장소, 일정, 뉴스, 커뮤니티가 모두 같은 카드가 되어 의미가
평준화된다. 본 앱에서는 경로·티켓·스탬프처럼 도메인별 표현을 제한적으로
사용하는 편이 정보 탐색에 유리하다.

### 커뮤니티도 메인 하단 바를 계속 사용

전역 일관성은 높지만 커뮤니티 내부의 세 목적지를 빠르게 오가는 기존 사용성을
잃는다. 사용자 결정에 따라 커뮤니티 전용 하단 바를 유지한다.

## 영향

- 기존 대형 루트 페이지는 즉시 삭제하지 않고 새 sibling 모듈과 병행해 회귀
  비교가 가능하게 한다. 라우팅 전환이 안정화된 뒤 제거한다.
- 유저·이벤트 상세에 한정하지 않고, 실제 라우터에 연결된 인증·설정·작품·멤버·
  성우·음악·응원·명대사·칭호·덕력·즐겨찾기·검색·알림·장소·방문·커뮤니티
  작성·상세 화면까지 같은 문서형 시각 계약으로 전환한다. 세부 계약은
  `ADR-20260715-route-wide-design-contract.md`에서 규정한다.
- 여행 노트의 실제 데이터 계약이 추가되면 베타 상태를 서버 기반 목록으로
  교체하되 장소·방문·이벤트 ID를 명시적으로 연결해야 한다.
